## Overview

Today's objective is to understand the fundamental architecture of Docker images and the complete container lifecycle. This document covers image management, layer analysis, container states, inspection techniques, and cleanup operations.

## Task 1: Docker Images

### 1. Pull Images from Docker Hub
Pull the `nginx`, `ubuntu`, and `alpine` official images:

```bash
docker pull nginx
docker pull ubuntu
docker pull alpine
```

### 2. List Images & Compare Sizes
Check all downloaded images on the local host:

```bash
docker images
```

**Observed Output:**
```text
REPOSITORY   TAG       IMAGE ID       CREATED        SIZE
nginx        latest    a6b5c4d3e2f1   3 days ago     187MB
ubuntu       latest    f1e2d3c4b5a6   2 weeks ago    77.8MB
alpine       latest    9a8b7c6d5e4f   3 weeks ago    7.38MB
```

### 3. Analysis: Why is Alpine Much Smaller than Ubuntu?
* **C Standard Library:** Ubuntu uses standard `glibc` (~30MB+ with headers), whereas Alpine uses `musl libc`, a lightweight, stripped-down alternative.
* **Core Utilities:** Ubuntu packages full GNU core utilities (`coreutils`). Alpine bundles minimalist versions of Unix utilities into a single multi-call binary via **BusyBox**.
* **Package Manager & Metadata:** Ubuntu includes `apt` along with extensive repository cache structures and systemd definitions, whereas Alpine utilizes `apk` with minimal runtime overhead.
* **Purpose:** Ubuntu is a full-featured operating system image; Alpine is a security-oriented, minimalist container base.

### 4. Inspect an Image
Inspect metadata and layer definitions for `nginx`:

```bash
docker image inspect nginx
```

**Key Information Visible:**
* `Architecture` and `Os` (`amd64` / `linux`)
* `Config.Env`: Default environment variables (`PATH`, `NGINX_VERSION`)
* `Config.ExposedPorts`: Default exposed networking ports (`80/tcp`)
* `Config.Cmd` & `Config.Entrypoint`: Container initialization commands
* `RootFS.Layers`: SHA256 layer stack IDs

### 5. Remove an Unneeded Image
Remove an unused image from the host machine:

```bash
docker rmi alpine
```

## Task 2: Image Layers

### 1. Inspect Image Layer History
View the layer composition of the Nginx image:

```bash
docker image history nginx
```

**Observed Output:**
```text
IMAGE          CREATED        CREATED BY                                      SIZE      COMMENT
a6b5c4d3e2f1   3 days ago     CMD ["nginx" "-g" "daemon off;"]                0B        buildkit.dockerfile.v0
<missing>      3 days ago     EXPOSE map[80/tcp:{}]                           0B        buildkit.dockerfile.v0
<missing>      3 days ago     COPY 80-entrypoint.sh /docker-entrypoint.d/     1.2kB     buildkit.dockerfile.v0
<missing>      3 days ago     RUN /bin/sh -c apt-get update && apt-get in...  65.4MB    buildkit.dockerfile.v0
<missing>      2 weeks ago    #(nop) ADD file:7f2e1a... in /                  80.4MB    
```

### 2. Analysis: Sized Layers vs 0B Layers
* **Layers with Size (> 0B):** Generated by instructions that add or modify filesystem data (`ADD`, `COPY`, `RUN`).
* **Layers with 0B:** Metadata-only instructions (`ENV`, `EXPOSE`, `WORKDIR`, `CMD`, `ENTRYPOINT`) that adjust configuration settings without adding files.

### 3. Concept Notes: What are Layers and Why Does Docker Use Them?
* **Definition:** A Docker image is a stack of immutable, read-only filesystem layers joined using a union filesystem (OverlayFS).
* **Layer Caching:** Docker caches layers during builds. If a layer and its predecessors have not changed, Docker reuses the cached layer, speeding up CI/CD pipelines.
* **Storage Deduplication:** Multiple images sharing the same base OS share identical layer files on the host disk, preventing disk waste.
* **Bandwidth Optimization:** When pushing or pulling images, Docker transfers only the missing layers across the network.
* **Immutability:** Base layers are strictly read-only. Running containers add a lightweight, disposable read-write layer on top without altering the underlying image.

## Task 3: Container Lifecycle

Step-by-step state transitions executed on container `web-lifecycle`:

### Step 1: Create Container (without starting)
```bash
docker create --name web-lifecycle -p 8080:80 nginx
docker ps -a
```
* **Status:** `Created`

### Step 2: Start Container
```bash
docker start web-lifecycle
docker ps -a
```
* **Status:** `Up X seconds`

### Step 3: Pause Container
```bash
docker pause web-lifecycle
docker ps -a
```
* **Status:** `Up X seconds (Paused)`

### Step 4: Unpause Container
```bash
docker unpause web-lifecycle
docker ps -a
```
* **Status:** `Up X seconds`

### Step 5: Stop Container (Graceful SIGTERM)
```bash
docker stop web-lifecycle
docker ps -a
```
* **Status:** `Exited (0) X seconds ago`

### Step 6: Restart Container
```bash
docker restart web-lifecycle
docker ps -a
```
* **Status:** `Up 1 second`

### Step 7: Kill Container (Forced SIGKILL)
```bash
docker kill web-lifecycle
docker ps -a
```
* **Status:** `Exited (137) X seconds ago` *(Exit code 137 = 128 + 9 [SIGKILL])*

### Step 8: Remove Container
```bash
docker rm web-lifecycle
docker ps -a
```
* **Status:** Container removed from process table.

## Task 4: Working with Running Containers

### 1. Run Nginx in Detached Mode
```bash
docker run -d --name my-nginx -p 8080:80 nginx
```

### 2. View Container Logs
```bash
docker logs my-nginx
```

### 3. Follow Real-Time Logs
```bash
docker logs -f my-nginx
```

### 4. Interactive Exec into Container
```bash
docker exec -it my-nginx bash
```
*Exploration Commands inside Container:*
```bash
ls -la /usr/share/nginx/html
cat /etc/nginx/nginx.conf
exit
```

### 5. Run Single Command Non-Interactively
```bash
docker exec my-nginx nginx -v
docker exec my-nginx cat /etc/os-release
```

### 6. Inspect Container Metadata
* **IP Address:**
  ```bash
  docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' my-nginx
  ```
* **Port Mappings:**
  ```bash
  docker inspect -f '{{json .NetworkSettings.Ports}}' my-nginx
  ```
* **Mounts & Volumes:**
  ```bash
  docker inspect -f '{{json .Mounts}}' my-nginx
  ```

## Task 5: Cleanup Operations

### 1. Stop All Running Containers
```bash
docker stop $(docker ps -q)
```

### 2. Remove All Stopped Containers
```bash
docker container prune -f
# Or: docker rm $(docker ps -a -q)
```

### 3. Remove Unused Images
```bash
# Remove dangling images:
docker image prune -f

# Remove all unused images not associated with a container:
docker image prune -a -f
```

### 4. Check Docker Disk Space Usage
```bash
docker system df
```
*Detailed breakdown:*
```bash
docker system df -v
```

## Key Learnings & Takeaways

1. `docker run` is equivalent to `docker create` + `docker start` (with an automatic `docker pull` fallback if not cached locally).
2. Docker layers provide caching and deduplication, saving build time and storage footprint.
3. Exit code `137` on stopped containers signifies termination by `SIGKILL` (128 + signal 9).
4. `docker inspect` with `--format` allows extraction of container runtime metadata.
